# 从模型原理到 LLM 应用

## 目标与边界

这门课先回答“模型怎样从文本学会预测”，再回答“怎样把模型放进可靠的应用”。
从零指能够解释、实现和验证核心机制；张量计算与自动求导采用 PyTorch，必要时用小规模手算或标准库实验交叉验证。

模型主线的产物是一个能训练、评估、保存、恢复和生成文本的小型 decoder-only Transformer。
小模型用来理解机制，不预设它能达到通用聊天模型的质量。
应用阶段接入成熟的预训练或指令模型，并明确区分模型架构、权重、提示词、检索和外部工具的职责。

## 怎么安排每一课

每课只建立一个明确、可检查的小能力，通常引入 1–2 个紧密相关的新机制。
预计用时 30–60 分钟，包含阅读、预测、实验和简短复盘；准备课约 20–30 分钟。
这个时间用于控制教材范围，学习者可以按自己的节奏完成。若一课出现多个独立实验、
较长的先修知识补课，或预计超过 60 分钟，就拆成后续课，不靠压缩讲解容纳更多内容。

数学、Python 语法与框架用法在首次需要时补齐。必学内容与选读材料分开，选读不作为结课条件。
一课通常只要求一次预测、一个贯穿实验和一到两个解释，必答项合计 2–3 个。
导师提供数据读取、日志和命令入口等配套设施，学习者聚焦新增机制。
阶段结束时安排轻量整合，复用前面实现，不在整合课里同时引入一批新机制。

## 运行规模与验证

前期使用 CPU 和微型数据验证正确性。加速器用于后续提速：Apple Silicon 可以评估 MPS，
有 NVIDIA GPU 时可以评估 CUDA；实际支持情况在引入 PyTorch 时检查。
较大的预训练模型和微调实验根据实际内存选择尺寸，保留小样本与小步数的可运行路径。

模型阶段至少区分训练损失、验证损失和生成样例。应用阶段分别记录任务成功率、检索质量、延迟与调用成本。
一个看起来不错的回答不能替代固定评估集；模型或数据配置变化后重新比较。

训练实验记录版本、设备、种子、数据切分和关键超参数。固定种子只控制相应随机过程，
不同硬件、库版本和并行计算仍可能产生差异。
